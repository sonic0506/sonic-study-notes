# 지식 그래프 학습 노트 설계

## 목적
학습한 내용을 Markdown으로 쌓고, 문서끼리 선행·관련 관계로 연결된 지식 그래프로 관리한다.
Obsidian으로 작성하고 그래프를 보며, 블로그(Velog, Tistory 등)에는 직접 복사해서 게시한다.
새 문서는 `/add-note` 스킬로 넣는다. 스킬은 AI 티 제거(humanizer)와 기존 지식베이스와의 연결을 자동으로 처리한다.

## 폴더 구조
```
sonic-study-notes/            Obsidian Vault 루트, git 저장소
├── inbox/                    처리 전 초안 (파일명 자유)
├── notes/                    처리 완료된 지식 문서 (하위 폴더 없음)
├── attachments/              이미지
├── templates/note.md         문서 템플릿
├── .claude/skills/add-note/SKILL.md
├── .obsidian/app.json        새 문서는 notes/, 첨부는 attachments/, 위키링크 사용
├── .obsidian/templates.json  템플릿 폴더는 templates/
└── .gitignore                .obsidian/workspace*.json
```
- 분류는 폴더가 아니라 `tags`로 한다. 한 문서가 여러 분야에 걸칠 수 있기 때문이다.
- 파일명은 영문 소문자 kebab-case로 짓고, 이것이 문서 ID가 된다. 폴더가 하나라서 파일명이 겹치지 않는다.

## 문서 형식
```yaml
---
aliases: [Docker Compose, 도커 컴포즈]
tags: [docker, devops]
prerequisites:
  - "[[docker]]"
related:
  - "[[docker-network]]"
status: draft          # draft | published
created: 2026-10-01
---
```
- `aliases`는 사람이 읽는 제목이자 링크 자동완성 검색어(`[[도커` 입력 시 검색됨)이다. 블로그 제목도 여기서 가져온다.
- 링크는 반드시 따옴표 붙은 YAML 리스트로 쓴다. 따옴표가 없으면 중첩 리스트로 해석되어 링크로 인식되지 않는다.
- 블로그에 게시한 뒤에는 `status: published`로 바꾸고, 필요하면 `published_url`을 추가한다.

## 링크 규칙
- `prerequisites`: 이 문서를 이해하려면 먼저 알아야 하는 문서다. 방향은 현재 문서 → 선행 문서. 순환은 허용하지 않는다.
- `related`: 대등한 관계다. 한쪽 문서에만 적고, 반대쪽에서는 백링크로 본다.
- 본문의 `[[링크]]`도 허용한다.
- 아직 없는 문서로의 링크(미작성 링크)도 허용한다. 앞으로 쓸 글 목록 역할을 한다.
- 그래프 뷰에서는 두 관계가 같은 모양의 선으로 보인다. 관계 종류는 Properties 패널에서만 구분된다.

## `/add-note <inbox 파일>` 스킬
입력은 `inbox/`에 있는 초안 한 개다. 아래 순서대로 처리한다.

1. **원본 보관**: `git add <초안>`. 원본을 index에 남겨서 이후 변경을 diff로 볼 수 있게 한다.
2. **정규화**
   - 파일명(slug)을 정한다. 기존 문서에 같은 개념의 미작성 링크가 있으면 그 이름을 그대로 쓴다. 이렇게 하면 기존 링크가 자동으로 연결된다.
   - slug가 `notes/`에 이미 있으면 중단하고 보고한다. 기존 문서와 합칠지는 사용자가 정한다.
   - 템플릿에 맞춰 프론트매터를 채운다(aliases, tags, status: draft, created). 초안에 이미 있는 값은 유지한다.
3. **휴머나이즈**: `humanizer:humanizer` 스킬로 본문 산문을 수정하고 그대로 덮어쓴다. 코드 블록, 명령어, 기술 용어, 기존 위키링크, 프론트매터는 건드리지 않는다. 의미를 바꾸지 않는다. 링크 추가 전에 실행한다.
4. **연결 분석**: `notes/*.md`의 프론트매터와 제목(헤딩)을 모두 읽고 관계를 판단한다. 개념을 실제로 다룰 때만 연결하고, 단어가 한 번 언급된 것만으로는 연결하지 않는다.
5. **연결 적용**
   - 새 문서의 `prerequisites`와 `related`를 채운다.
   - 새 문서가 기존 문서의 선행 지식이면 기존 문서의 `prerequisites`에 추가한다. 기존 문서는 프론트매터만 수정하고 본문은 고치지 않는다.
   - 새 문서 본문에서 기존 문서 개념이 처음 나오는 곳 한 번만 `[[slug|원래 표현]]`으로 바꾼다.
   - 다뤄야 하지만 아직 문서가 없는 개념은 미작성 링크로 남긴다.
   - 선행 관계에 순환이 생기는 연결은 추가하지 않고 보고에 적는다.
6. **이동**: `git mv <초안> notes/<slug>.md`.
7. **보고**: 이동 경로, 휴머나이즈 수정 수, 추가한 링크, 수정한 기존 문서, 새 미작성 링크, 건너뛴 순환을 알린다. 커밋하지 않는다.

사용자는 `git diff`로 원본 초안 대비 모든 변경과 기존 문서 수정을 확인한다. 그 뒤 커밋하거나 `git restore`로 되돌린다.

## 블로그 게시 (수동)
1. 프론트매터를 뺀 본문을 복사한다.
2. `[[링크]]`를 블로그 URL이나 일반 텍스트로 바꾼다.
3. `status: published`로 바꾸고, 필요하면 `published_url`을 추가한다.

## 범위 밖 (필요해지면 추가)
- 위키링크를 블로그 링크로 자동 변환하는 스크립트: 직접 복사하는 게 번거로워질 때.
- 주제별 목차(MOC) 문서: 그래프만으로 길을 찾기 어려워질 때.
- 관계 종류를 그래프에서 구분하는 플러그인(Juggl, Breadcrumbs): 필요해질 때.
- 탐색용 인덱스나 임베딩: 문서가 수백 개를 넘어 전체를 읽기 어려워질 때. 그 전에 태그로 후보를 줄이는 단계부터 추가한다.

## 검증
- [ ] 그래프 뷰에서 예시 문서 `docker-compose`와 `docker`가 이어지고, `docker` 백링크에 `docker-compose`가 보인다.
- [ ] 미작성 링크가 그래프에 미작성 노드로 보인다.
- [ ] 템플릿을 삽입하면 `created`에 날짜가 들어간다(Templates 코어 플러그인이 켜져 있는지 확인).
- [ ] `[[도커`를 입력하면 자동완성에 `docker`가 뜬다.
- [ ] `inbox/`에 테스트 초안을 넣고 `/add-note`를 실행한다. 파일이 `notes/`로 옮겨지고, 링크가 추가되고, 기존 문서의 선행 지식이 갱신되고, `git diff`에 원본 대비 변경이 보이는지 확인한다.
